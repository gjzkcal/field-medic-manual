# Security Policy / セキュリティポリシー

Field Medic Manual の脆弱性の報告先と、アプリが扱うデータ・通信・鍵についてまとめます。

## 脆弱性の報告 / Reporting a vulnerability

**公開の Issue には書かず、GitHub の [Report a vulnerability](https://github.com/gjzkcal/field-medic-manual/security/advisories/new) から非公開で報告してください。** 再現の手順、影響する版、想定される影響を書いてもらえると助かります。

Please do not open a public issue. Report privately through [GitHub's private vulnerability reporting](https://github.com/gjzkcal/field-medic-manual/security/advisories/new). Reports in English are welcome.

個人の開発なので、返信の期限は約束できません。修正を公開したあとに、報告者の希望に合わせてアドバイザリで内容を公開します。

## 対象の版

修正は最新の版にだけ入れます。古い版は、更新してから確かめてください。

| 対象                           | サポート |
| ------------------------------ | -------- |
| デスクトップ版の最新のリリース | ○        |
| Web 版（公開中のサイト）       | ○        |
| それより古い版                 | ×        |

## 依存の脆弱性への対応

依存の既知の脆弱性は、`pnpm audit`・`cargo audit`（週 1 回と lockfile の変更時）で確かめています。修正が公開されてから、次の期限までに対応します。

| 深刻度         | 期限                                       |
| -------------- | ------------------------------------------ |
| Critical・High | 7 日                                       |
| Medium         | 30 日                                      |
| Low            | 次のリリース。見送るときは理由を記録します |

アプリに影響しない場合（開発時だけ使う依存で、配布物に入らないなど）は、理由を記録して見送ることがあります。

配布する部品の一覧（SBOM、SPDX 形式）は、版ごとに [Releases](https://github.com/gjzkcal/field-medic-manual/releases) に添付します。GitHub の依存グラフから作るので、タグを付けた時点のデフォルトブランチの内容です。

## 通信

**デスクトップ版が自分から通信するのは、更新の確認とダウンロードだけです。** 利用状況の収集や、エラーの送信はしません。

| 通信先                                                                                          | 目的                                   | 送るもの                                                               |
| ----------------------------------------------------------------------------------------------- | -------------------------------------- | ---------------------------------------------------------------------- |
| `https://github.com/gjzkcal/field-medic-manual/releases/`（と GitHub のダウンロード用のホスト） | 起動時の更新の確認、更新のダウンロード | 通常の HTTPS のリクエストのみ（IP アドレスなどは GitHub から見えます） |

**Web 版** は GitHub Pages で配信しています。ページの読み込みのほかに外部へは接続しません（CSP で制限しています）。

本文のリンクは、押したときにだけ既定のブラウザ（Web 版は新しいタブ）で開きます。開けるのは `http`・`https` だけです。

## 保存するデータ

アカウントや個人情報、認証情報は扱いません。次のデータを利用者の手元にだけ保存し、暗号化はしていません。

| データ                                           | 場所（デスクトップ版）                                          | 分類                             |
| ------------------------------------------------ | --------------------------------------------------------------- | -------------------------------- |
| 同梱のマニュアル・クイック表・フロー、検索の索引 | `%APPDATA%\com.gjzkcal.fieldmedicmanual\`（SQLite と `assets`） | 公開の情報                       |
| 設定、ホットキー、お気に入り、閲覧の履歴、同義語 | 同上                                                            | 利用者の好み。外部には送りません |
| ウィンドウの位置と大きさ                         | 同上                                                            | 利用者の好み                     |
| ログ                                             | `%LOCALAPPDATA%\com.gjzkcal.fieldmedicmanual\logs\`             | 下の「ログ」を参照               |

Web 版は設定だけをブラウザの localStorage に置きます。お気に入りと履歴は保存しません。

## ログ

デスクトップ版は、問題の調査のためにログを手元のファイルに書きます。**外部には送りません。** 報告のために共有するかどうかは利用者が決めます。

- 形式: 1 件 1 行の JSON（`ts`・`level`・`target`・`msg`）。時刻は UTC です。
- 保持: 1 ファイル 1 MiB までで、古いものは 5 世代まで残して消します。
- 書く内容: 起動、入力の検証や権限で拒否した操作、内部のエラー、画面の例外（スタックを含む）、パニック、更新の確認とインストールの失敗。
- 書かない内容: 検索語、お気に入り、履歴、マニュアルの本文。
- 改行と制御文字はエスケープし、1 件の長さに上限を設けています。ログのファイルは利用者の権限で読み書きできるので、改ざんの検知はできません。

Web 版はログを書きません。

## 暗号と鍵

アプリは自前の暗号の処理を持ちません。使うのは次のものだけです。

| 用途             | 方式                                                      | 鍵の扱い                                                                                                                                |
| ---------------- | --------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| 更新の検証       | minisign（Ed25519）の署名。検証は Tauri の updater        | 公開鍵はアプリに同梱。秘密鍵とパスワードは GitHub Actions の Environment `release` の Secret に置き、タグのワークフローからだけ使います |
| 通信             | HTTPS（TLS）。証明書の検証を無効にしません                | OS と rustls のルート証明書                                                                                                             |
| 画像のファイル名 | SHA-256。重複の検出用で、セキュリティの目的では使いません | なし                                                                                                                                    |

秘密鍵が漏れたときは、鍵を作り直して新しい公開鍵を入れた版を公開し、Releases と README で知らせます。古い版は新しい鍵の更新を受け付けないので、手動で入れ直してもらう必要があります。

インストーラにはコード署名をしていません。Windows の SmartScreen の警告が出ることがあります。

## 検証の基準

[OWASP ASVS 5.0.0](https://github.com/OWASP/ASVS) の Level 2 を基準に見直しています。認証・セッション管理・トークン・OAuth・WebRTC の章は、機能がないので対象外です。次の項目は例外で、完全準拠ではありません。

| 要件                                                  | 例外の理由                                                                            | 補う手段                                                                               |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| V3.4.1（`includeSubDomains`）、V3.4.3、V3.4.4、V3.4.6 | GitHub Pages ではレスポンスヘッダを付けられない（Web 版）                             | meta の CSP（`object-src 'none'`・`base-uri 'none'`）。iframe の中では本文を出しません |
| V3.5.4                                                | `gjzkcal.github.io` の origin を同じアカウントのほかの Pages と共有する（Web 版）     | 保存した設定は読むときに検証します                                                     |
| V16.3.2（一部）                                       | ウィンドウの権限（capability）の拒否は Tauri の内部で処理され、アプリから記録できない | アプリ自身の判定による拒否は記録します                                                 |
| V16.4.2                                               | ログは利用者の PC にあり、利用者本人からは保護できない                                | ログに機微な情報を書きません                                                           |
| V16.4.3                                               | ログを別のシステムへ送らない（通信は更新の確認だけという設計）                        | 外部に送らないことを優先します                                                         |
